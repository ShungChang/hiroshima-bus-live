# ひろしま バスライブ

広島県バス協会のGTFSオープンデータを利用し、ブラウザー上でバスの位置・便情報・お知らせを表示する初期版です。

## まず起動する（Windows / Mac / Linux）

**Node.js 22以上**をインストールし、このリポジトリをダウンロード・展開してください。
そのフォルダーでターミナルを開き、次を実行します。

```sh
npm start
```

ブラウザーで **http://127.0.0.1:8787** を開きます。追加パッケージのインストールやAPIキーは不要です。ターミナルを閉じると取得サーバーも止まります。

画面のHTMLファイルを直接ダブルクリックしても動作しません。上記サーバーを起動してください。地図ライブラリー（Leaflet 1.9.4 / unpkg）とOpenStreetMapの背景地図の読込にはインターネット接続が必要です。

## できること

- 17事業者の切替、または全事業者の表示。初期表示は広島電鉄。
- 車両位置の地図表示と、位置が配信されていない便の一覧表示。
- 路線・行先・車両名・便ID・停留所の検索。
- 遅延・早発、次停留所の予測遅延、運休の表示（元データに値がある場合）。
- 運行のお知らせの表示。日本語テキストを優先。
- 取得失敗時は前回のデータを保持し、その旨を表示。90秒を超えた位置・時刻不明の位置は灰色表示。
- 自動更新の一時停止と再開。画面を非表示にすると新しい更新サイクルを停止。

表示中のブラウザーは取得完了後15秒で次回取得します。通信時間が加わるため、厳密な毎時0・15・30・45秒の更新ではありません。画面を非表示にした直前の取得は完了する場合があります。ページを閉じている間の追跡・保存は行いません。

## データの範囲と読み方

データ提供：[広島県バス協会GTFSオープンデータサイト](https://www.bus-kyo.or.jp/gtfs-open-data)（CC0）。配信URL確認：2026-10-21。

| 対象 | 対応 |
| --- | --- |
| 広島電鉄、広島バス、広島交通、芸陽バス、備北交通、JRバス中国 | 車両位置 / TripUpdate / Alert |
| エイチ・ディー西広島、フォーブル、ささき観光、呉市生活バス、廿日市市自主運行バス、朝日交通阿戸熊野線、おのみちバス | 車両位置 / TripUpdate / Alert |
| 中国バス、鞆鉄道、井笠バスカンパニー | 車両位置 / TripUpdate / ServiceAlert |
| 江田島バス | TripUpdateのみ（位置配信なし） |

公式ページに配信URLがあることと、現在そのフィードが正常・完全であることは別です。対象外路線、運行時間外、配信中断、静的データとのID不一致があり得ます。表示台数は全運行台数ではありません。呉市生活バスは公式ページにも一部対象外路線ありとの記載があります。

遅延が未配信の便を定刻とは扱いません。「3分以上の遅れ」は本ビューアーの表示上の閾値で、事業者の運行評価基準ではありません。次停留所の到着／出発遅延を取得できる場合は「次停留所予測」、便単位のdelayを使用する場合は「便の遅延」と区別します。到着時刻のみでdelay値がない場合は、時刻表から推算せず「遅延情報なし」にします。

車両のtimestampを優先し、なければ配信timestampを表示します。ただし測位時刻不明の車両を新鮮な位置とみなさず灰色にします。TripUpdateとの照合はtrip_idに加えてstart_date / start_time / route_id / direction_idの矛盾を確認し、候補が曖昧なら照合しません。

## 取得構成

HTML/CSS/JavaScriptの画面 → 同梱のNode.jsサーバー → 公式GTFS配信元、という構成です。ブラウザーが配信元のCORSに依存しないよう、サーバー側で取得・デコードします。

- リアルタイムは**URLごと・取得完了後15秒以上**のキャッシュ。失敗時にも15秒待機し、同時リクエストを共有します。
- 静的GTFSは現在データ `current_data.zip`（他社は公式の対応URL）を使用。取得成功後6時間キャッシュ、失敗時は60秒待機。
- 現在は利用者が画面を開いている間のリクエストに応じて取得。サーバーによる常時ポーリングは行いません。
- 配信元への同時通信は4本まで。任意の外部URLを転送する機能はありません。
- 差分フィードの削除を反映。初回から差分だけが届いた場合は完全な情報として表示せず、全量データ待ちのエラーを表示します。
- キャッシュはサーバープロセス内で共有します。**公開時は1プロセス・1レプリカ**で動かしてください。複数インスタンスでは共有キャッシュが別途必要です。

## GitHubでの利用と公開

ソースはこのGitHubリポジトリで管理します。`Check`ワークフローが構文とテストを確認します。

### 推奨：Node.jsサーバーから画面も配信

Node.js 22対応のホスティングにリポジトリを配置し、起動コマンドを `npm start`、環境変数 `HOST=0.0.0.0` に設定します。サービス指定の `PORT` を使用できます。HTTPSの設定・料金は利用するホスティング側で確認してください。Dockerfileも付属しています。

この構成では画面とAPIが同一オリジンとなり、接続設定は空欄のままで動作します。

### GitHub PagesでHTML画面だけを公開する場合

**GitHub PagesはNode.jsサーバーを実行できません。別途APIサーバーのホスティングが必要です。** GitHub Actionsによる15秒ごとのデータ取得は行いません。

1. 別ホストで上記APIサーバーをHTTPS公開します。
2. APIサーバーの環境変数 `ALLOWED_ORIGIN=https://shungchang.github.io` を設定します。パス・末尾スラッシュは付けません。
3. リポジトリの **Settings → Pages → Source → GitHub Actions** を選びます。
4. **Actions → Publish frontend to GitHub Pages → Run workflow** を実行します（公開は手動です）。
5. 公開画面の **接続設定** にAPIサーバーのHTTPS URLを入力します。この設定はブラウザーごとに保存されます。

## 検証

```sh
npm run check
npm test
```

テストは合成したProtocol Buffer・ZIP・HTTP配信を使用します。負数の遅延、位置座標、差分削除、不正データ、CSV引用符、キャッシュの同時取得共有／失敗時の間隔、CORS、便の同一性、古いデータの判定を検証します。公式配信への高頻度テストは行いません。

開発環境では外部ドメインの名前解決とブラウザー操作が利用できなかったため、**公式バイナリの取得・実車両表示・地図描画の目視確認は未完了**です。配信URLは公式ページから確認済みですが、稼働保証を意味しません。公開前にネット接続可能な環境で、車両が現れること、2回以上更新すること、事業者切替、一時停止、運行時間外の表示をご確認ください。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `public/index.html`, `styles.css`, `app.mjs`, `model.mjs` | 画面、地図、表示用データ処理 |
| `server.mjs` | 静的配信、取得API、通信制限 |
| `lib/providers.mjs` | 公式配信URLの一覧 |
| `lib/protobuf.mjs` | GTFS Realtimeの必要項目のデコーダー |
| `lib/static.mjs` | GTFS ZIP / CSVと表示用索引 |
| `lib/cache.mjs` | 取得共有、成功・失敗キャッシュ |
| `test/core.test.mjs` | データ処理とHTTPのテスト |

実装は[公式GTFS Realtimeスキーマ](https://github.com/google/transit/blob/master/gtfs-realtime/proto/gtfs-realtime.proto)を参照。未知フィールドは読み飛ばします。完全なGTFS検証器・経路検索・到着時刻の時刻表計算・運行履歴の記録は含みません。
